Architecture Deep-Dive

Server-as-Referee & Anti-Cheat Engine

Strictly adhering to Hackathon Rule #1: Zero client-side trust.

🛡️ Authoritative Server Clock
  • Client clocks are never trusted. Server dictates round start, duration, and hard cutoff (+350ms network transit buffer).
  • Correct answer keys are never transmitted in question_start payloads; answers exist strictly on the backend.
  • Submissions after the server timestamp cutoff are rejected deterministically by the authoritative referee.
🔀 Candidate Option Shuffling
  • In campus computer labs, students glance at adjacent screens.
  • AptiQuiz randomizes option order per player: Option A on Player 1's screen is Option C on Player 2's screen.
  • Host has full control via toggle: Shuffle Questions and Shuffle Options (Anti-Cheat).

Latency Engineering

Network Delay Fairness Algorithm

Ensuring students on slower college 4G aren't penalized against campus LAN gigabit connections.

How Latency Compensation Works:
// Bounded Half-RTT Latency Compensation const estimatedPing = Math.min(player.ping || 60, 400); const oneWayTransit = Math.round(estimatedPing / 2); const fairResponseTime = Math.max(200, elapsedMs - oneWayTransit); const timeRemaining = Math.max(0, durationMs - fairResponseTime);

Client ping is continuously sampled via non-blocking heartbeat pings. The server computes effective response time relative to when the question actually arrived on the candidate's screen.

Zero-Loss Reconnection:
  • Temporary Wi-Fi drops or browser reloads automatically trigger reconnect_room with persistent UUID.
  • Restores current question timer, cumulative score, highest streak, and topic stats seamlessly.
  • Benchmarked and verified in our 50-player test suite with 100% state restoration.
